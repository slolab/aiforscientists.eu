# aiforscientists.eu

Source for the AI for Scientists website: recipes and skill briefs for giving research tasks to agents.
MkDocs Material, deployed to GitHub Pages from `main` (`.github/workflows/docs.yaml`).
Sister site: aiforscience.eu (`../aiforscience.eu`), whose theme this site copies.

## Commands

- `uv sync`: install dependencies
- `uv run mkdocs serve`: local preview at http://127.0.0.1:8000
- `uv run mkdocs build --strict`: build; fails on broken internal links. Run before every PR.

## Writing style (hard rule)

- No em-dash asides. Use a period, colon, comma, or parentheses.
- No "not just X but Y" constructions.
- No inflated adjectives or transitions ("crucial", "seamlessly", "robust" as filler).
- Short declarative sentences. Every word carries information.
- One sentence per source line, blank line between paragraphs.
- Examples carry no names or identifying details unless the contributor asked to be named.

## Recipes (docs/recipes/NN-slug.md)

Recipe NN follows point NN of the Comment "Delegate what you can check: ten lessons on AI agents in research".
New recipes from contributors get the next free number.

```yaml
---
title: <the recipe, as an instruction>
nav_title: "<short label for the sidebar>"
recipe_id: R-NN
status: draft | tried | reproduced
stage: Prepare for agents | Think with agents | Implement with agents
verifiability: Machine-checkable | Expert-checkable | Hard to verify
autonomy: <how much the agent may do alone, one line>
first_added: YYYY-MM-DD
last_reviewed: YYYY-MM-DD
skills:
  - name: <skill name, matching docs/skills/<name>.md>
    does: <one line>
practices:
  - title: <aiforscience.eu practice nav title>
    slug: <practice file slug on aiforscience.eu>
    note: <how this recipe follows it>
tags: [<stage>, <verifiability>]
comments: true
---
```

Body, in this order: `<!-- RECIPE_TITLE -->`, `## Summary`, `## Steps`, `## How to check the output`, `## Examples`, `## Known problems`, `<!-- RECIPE_SKILLS -->`, `<!-- RECIPE_PRACTICES -->`, `## Change history` (dated bullets, newest first).
`hooks/recipe_pages.py` fills the placeholders from the frontmatter.

`reproduced` needs an example from a second, independent group on the page.

## Skill briefs (docs/skills/<name>.md)

A brief describes a skill so that anyone's agent can build a local version.
Everything institute-specific is a question under `local`, never a value.
The whole page is generated by `hooks/skill_pages.py` from the frontmatter; the body is only `<!-- SKILL_PAGE -->`.
The hook also writes `site/skills/<name>/brief.md` for agents to fetch.

```yaml
---
title: <name>
skill: <name>
status: brief | tried | reproduced
comments: true
recipe: <recipe file slug, e.g. 10-automate-paperwork>
check_level: machine | expert | hard
does: <one sentence>
inputs: [<what the user provides>]
outputs: [<what the skill returns>]
steps: [<general steps, in order>]
local: [<questions only a local user can answer: forms, systems, paths, rules, recipients>]
never: [<rules every local version keeps>]
check: <the check that runs every time>
test: <one test case with a known result>
versions:            # optional: local versions shared by their authors
  - who: <institute or group>
    url: <public link>
    note: <what it covers>
---

<!-- SKILL_PAGE -->
```

A brief contains no internal paths, names, credentials or institute forms.

## Workflow

- Content changes go through PRs to `main`. CI runs a strict build; a weekly job checks external links.
- Never push to `main` directly: a push deploys the site.
- Manuscript drafts (`*.docx`, `*.pdf`) stay out of git.
